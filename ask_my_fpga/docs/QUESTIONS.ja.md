# Ask My FPGA — 質問カタログ

> 🌐 言語: **日本語** · [English / 英語](QUESTIONS.en.md)
>
> FPGA についてエージェントに尋ねられるあらゆる種類の質問、その言い方、呼び出される
> ツール、返ってくる内容をまとめたものです。英語でも日本語でも普通に尋ねればよく、
> ツール名を自分で指定する必要はありません（エージェントが選びます）。

## 言い方の基本
- **アドレスではなく意味的な名前**を使う: `PI0_SET_KP`, `GAIN0_GAIN`, `DAC0`, `SCOPE0`。
- 経路の質問は**一度に1つのターゲット**（まず `DAC0`、次に `SCOPE0`）。
- **すべての回答にはタグ**が付く: `fact`（ライブ読み取り）、`config`（カタログ/固定
  配線由来）、`measurement`（サンプルから計算）、`unknown`。fact/measurement は観測値
  として信頼し、「解釈」とされたものは読み取り値ではなく推論。
- **ジェネレータ（ASG0/ASG1）は出力**でありレジスタではない — 「ASG1 で生成して」と
  尋ね、「ASG1 のレジスタを読んで」とは尋ねない。
- **書き込みはゲートされる**: エージェントがまずドライラン/計画を提示 → 承認 → 適用 →
  読み戻し検証。承認は「適用して」「OK」などで伝える。

## 1. 動いている?（環境・接続）
| 尋ね方（例） | ツール | 得られるもの |
|---|---|---|
| 「ステータスチェックして。」/「サーバに繋がる?」/「live か replay か?」/「どの config / device?」 | `get_status` | サーバ状態 + `config_file`, `device_id`, `mode` |
| 「登録デバイスは?」/「どのボードがアクティブ?」 | `get_sessions` | デバイスセッション + アクティブデバイス |
| 「今、出力/ジェネレータは動いてる?」 | `get_output_status` | ライブなジェネレータ/出力状態 |

## 2. 何がある?（探索）
| 尋ね方 | ツール | 得られるもの |
|---|---|---|
| 「FPGA のモジュールは?」/「DSP ブロック一覧。」 | `get_modules` | カタログモジュール **+ ジェネレータ**（ASG0/ASG1） |
| 「PI モジュールのレジスタは?」 | `get_modules` → `get_register_info` | モジュールのレジスタ名、続いて詳細 |
| 「PI0_SET_KP について教えて。」/「GAIN0_GAIN の型/format/アドレスは?」 | `get_register_info NAME` | 型（Q15.16 / float / uint32）・format・既定値・アドレス・アドレス共有エイリアス |

## 3. 現在の値は?（状態の読み取り）
| 尋ね方 | ツール | 得られるもの |
|---|---|---|
| 「今の PI0_SET_KP は?」/「GAIN0_GAIN を読んで。」/「LPF0_ALPAH の現在値は?」 | `get_parameter NAME` | 工学単位のデコード値 + 生 hex + アドレス（kind=fact） |
| 「PI と MIX のライブ状態を見せて。」/「GAIN の係数を全部。」 | `get_fpga_state [--modules PI,MIX]` | モジュール別のライブ値スナップショット |

## 4. どう配線されている?（経路と影響）
ここが「FPGA のあらゆる詳細」の核心です。
| 尋ね方 | ツール | 得られるもの |
|---|---|---|
| 「DAC0 への信号経路は?」/「SCOPE0 へどう届く?」/「DAC0 を上流にトレース。」 | `get_signal_path TARGET` | ライブ経路: 固定ホップ=config、mux セレクタ=fact、各 mux の `alternatives` |
| 「DAC0 に影響するモジュールは?」/「今 DAC0 に何が供給されている?」 | `get_signal_path TARGET` | `upstream_nodes`（現在の影響要因） — `get_modules` ではない |
| 「DAC0 に影響するパラメータ/レジスタは?」/「DAC0 信号に効く設定は?」 | `get_affecting_parameters TARGET` | 上流パス上の全モジュールの構成レジスタ |
| 「DAC0 に何を経路できる?」/「SCOPE0 に供給できるソースは?」 | `get_reachable TARGET` | ターゲットへ経路可能な全ソース + 直接の mux 選択肢 |
| 「ASG1 を DAC0 に経路できる? どうやって?」/「PI0 は SCOPE0 に届く?」 | `get_reachable TARGET --source SRC` | 経路可否 + それを行う正確なセレクタ書き込み |

## 5. 信号は実際どう見える?（測定）
| 尋ね方 | ツール | 得られるもの |
|---|---|---|
| 「DAC0 をキャプチャして RMS と主要周波数を。」/「チャンネル1にクリッピングある?」/「DC オフセットは?」 | `capture_analyze_signal` | スカラー要約: RMS, 平均/DC, ピーク, 最小, 最大, 主要周波数, 上位 FFT ピーク, クリッピング（kind=measurement） |
| 「なぜ DAC0 / SCOPE0 はノイズっぽい?」 | `get_signal_path` + モジュール状態 + `capture_analyze_signal` | まず観測（fact + measurement）、その後に考えられる原因を不確実性付きの解釈として提示。原因を事実として断定しない |

## 6. 変更する（書き込み — ドライラン → 承認 → 適用）
| 尋ね方 | ツール | 流れ |
|---|---|---|
| 「PI0_SET_KP を 0.5 に。」/「GAIN0_GAIN を 1.5 に。」/「BPF b0=0.1 b1=0.2 …」 | `set_parameter` | ドライラン差分 → 承認 → 適用 + 読み戻し検証 |
| 「ASG1 で 1 kHz・0.2 V の正弦波を生成。」/「ASG1 を停止。」 | `configure_asg` | ドライラン → 承認 → 適用 |
| 「ASG1 をチェーン経由で DAC0 へ。」 | `get_reachable` → `set_signal_path` | 実現可能性を確認 → mux 設定（ドライラン → 承認 → 適用） |
| 「DAC0 を SCOPE0 で、デシメーション64、取得開始。」 | `configure_scope` | ドライラン → 承認 → 適用 |

## 7. 診断ワークフロー（質問を連鎖させる）
- **「なぜ出力がノイズっぽい?」** → 信号経路（`get_signal_path`）→ ライブなモジュール状態
  （`get_fpga_state`）→ キャプチャ（`capture_analyze_signal`）。エージェントは観測を報告し、
  その後に *考えられる* 原因を解釈として挙げる。
- **「変更は効いた?」** → 適用後、エージェントは既に読み戻し検証済み。念のため
  `get_parameter NAME` を再度尋ねてライブ値を確認できる。
- **「DAC0 を LPF2 に繋ぎ替えると何が変わる?」** → `get_reachable DAC0 --source LPF2` が、
  コミット前に正確なセレクタ書き込みを示す。

## 8. エージェントが拒否/注意するもの
- ASG をレジスタのように読もうとする（出力なので → `configure_asg` を使う）。
- アドレスが共有/ビットパックされたレジスタへのワード全体書き込み（`set_parameter` が拒否）。
- カタログ/トポロジで解決できないもの → `unknown` として、推測せずそのまま返す。
