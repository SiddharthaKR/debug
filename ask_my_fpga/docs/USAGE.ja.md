# Ask My FPGA — 使い方ガイド

> 🌐 言語: **日本語** · [English / 英語](USAGE.en.md)
>
> このガイドは `USAGE.en.md` と章立てが一対一で対応しています。片方を編集したら、
> もう片方も同じように更新して同期を保ってください。

Ask My FPGA は、普通の言葉で質問・指示するだけで Red Pitaya FPGA の状態確認と設定が
できるツールです。ローカル LLM（gemma4）が、小さな Python ツールと既存の SharpRPL
C# API を通してハードウェアを読み書きします。

**英語でも日本語でも入力できます** — エージェントは入力した言語で返答します。
言語を切り替える設定はありません。

## 1. 前提条件
- **SharpRPL C# サーバー**が起動していて到達可能であること（例: `https://localhost:5000`）。
- **vLLM** が `http://127.0.0.1:8000/v1` で `gemma4` モデルを配信していること。
- **opencode** がインストールされていること。
- `config.json` が記入済みであること（base_url、catalog_path、device token）。
  無い場合は `config.example.json` をコピーして作成します。
- 信号ツール用の Python 依存関係: `pip install -r requirements.txt`。

## 設定すべき項目（config.json）
その他は妥当な既定値があります。ボードに合わせて設定が必要なのは次の3つだけです:

| 項目 | `config.json` のキー | 内容 |
|---|---|---|
| **デバイス ID** | `device_id` | どのボードと通信するか。`null` は `/api/status` の `activeDeviceId` に追従。数値を指定すると最大4台のうち1台に固定。 |
| **認証トークン** | `device_token` | すべての C# API 呼び出しに `x-device-token` ヘッダとして付与。`live` モードで必須。ローカルの `config.json` のみに保持（git には含めない）。 |
| **アクション** | `mode` | `"replay"` = フィクスチャ、ハードウェア不要 · `"live"` = 実機と通信。 |

## 信頼できる情報源（source of truth）— 2つのファイル
エージェントは配線やレジスタを勝手に作りません。次の2つのファイルを読み、
ハードウェアを定義するのはこれらだけです:

| ファイル | `config.json` のキー | 内容 |
|---|---|---|
| **settings.json** | `catalog_path` | レジスタカタログ: エイリアス → アドレス、型（Q15.16 / float / uint32）。 |
| **topology.yaml** | `topology_path` | データパス: 固定配線 + セレクタ（mux）。信号経路の質問に使用。 |

`live` モードでは、`catalog_path` はサンプルではなく**実際の** settings.json を
指すようにします。どちらのファイルもローカルに置き、git には含めません。

## 2. opencode を起動する
プロジェクトフォルダで:
```
cd ask_my_fpga
opencode
```
opencode は `AGENTS.md`（読み取りルール）と `WRITE_AGENTS.md`（書き込みルール）を
自動で読み込み、`tools/` と `write_tools/` のスクリプトのみ実行を許可します
（それ以外は実行できません）。

## 3. ハードウェア無しで試す（replay モード）
`config.json` の `"mode"` を `"replay"` にすると、同梱のフィクスチャ（模擬データ）で
動作します。動作の流れを学ぶのに最も安全な方法です。例えば次のように尋ねます:
- 「FPGA のモジュール一覧を表示して。」
- 「PI_SET_KP は何?」

## 4. 実機に接続する（live モード）
`config.json` の `"mode"` を `"live"` にし、実際の `base_url` と `catalog_path` を
設定します。まずサーバーを確認します:「ステータスチェックを実行して。」
（`get_status.py` を使用）。

## 複数の Red Pitaya — 1 セッション 1 台
ボードごとに専用の設定ファイルを用意し、各セッションを 1 台に固定します。
`config.rp1.example.json` / `config.rp2.example.json` を `config.rp1.json` /
`config.rp2.json` にコピーし、それぞれの `device_id` と `device_token`（ボードごとに
RTL が異なる場合は `catalog_path` / `topology_path` も）を設定してから、ボードごとに
セッションを起動します:
```
FPGA_AGENT_CONFIG=config.rp1.json opencode
FPGA_AGENT_CONFIG=config.rp2.json opencode   # 別のターミナルで
```
1 つのセッションは正確に 1 台の Red Pitaya と通信します — 複数台なら複数ターミナルで。
トークンはこれらのローカルファイルに保持し、チャットには決して載せません。

## 5. 質問する（読み取り — 常に安全）
読み取りはハードウェアを一切変更しません。プロンプト例:
- 「DAC0 への信号経路は?」
- 「DAC0 に影響するモジュールは?」
- 「DAC0 に影響するパラメータは?」
- 「GAIN0_GAIN の値は?」
- 「DAC0 をキャプチャして、RMS と主要周波数を教えて。」
- 「なぜ SCOPE0 はノイズっぽく見えるの?」（エージェントはまず観測結果を報告し、
  考えられる原因は「解釈」として提示します。原因を事実として断定しません。）

すべての回答にはタグが付きます: `fact`（実機から読み取り）、`config`（カタログ由来）、
`measurement`（サンプルから計算）、`unknown`（不明）。

## 6. FPGA を設定する（書き込み — 承認が必要）
書き込みはライブのルーティングや出力を変更するため、エージェントは常に
**ドライラン → 表示 → 確認 → 適用** の手順に従います:
1. 変更を依頼する（「ASG1 をチェーン経由で DAC0 にルーティングして」）。
2. エージェントが**ドライラン**を実行し、変更されるレジスタを正確に表示します
   （現在値 → 新しい値）。
3. **あなたが承認する。** 承認後に初めて `--apply` を付けて再実行します。
4. 各書き込みについて、読み戻しの `verified: true/false` を報告します。

プロンプト例:
- 「ASG1 を DAC0 にルーティングして。」→ 実現可能かを確認し、mux への書き込みを表示し、
  あなたの OK を待ってから適用します。
- 「GAIN0_GAIN を 1.5 に設定して。」
- 「ASG1 で 1 kHz・振幅 0.2 V の正弦波を生成して。」
  （ASG0/ASG1 は信号ジェネレータであり、レジスタカタログのモジュールではありません — 内部では
  エージェントが `configure_asg ASG1 --waveform SINE --freq 1000 --amp 0.2` を実行します。）
- 「SCOPE0 で LPF2 をタップして取得を開始して。」

変更が不可能な場合（例: そのノードはスコープでタップできない）、エージェントはその旨を
伝え、回避策があれば提案します。

## 7. 信号を止める
- 「ASG1 を止めて。」/「ASG1 のジェネレータを無効にして。」
- 「SCOPE0 の取得を停止して。」

## 8. 安全上の注意
- ライブ信号の再ルーティングは、実行中のロックや実験を中断させることがあります。
  ドライランは上書きされるルーティングを表示するので、承認前に必ず確認してください。
- エージェントは、そのメッセージ内であなたが明示的に承認しない限り、書き込みを
  適用しません。
- トポロジとレジスタカタログで許可された値のみ書き込み可能です。

## 9. 言語について
"answer in English"（英語で答えて）と言うか、英語で書き始めれば、エージェントが
切り替わります。レジスタ名・モジュール名・数値は、どちらの言語でも元の表記のまま
です。
